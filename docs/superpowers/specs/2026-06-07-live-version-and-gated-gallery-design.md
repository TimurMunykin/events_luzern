# Боевая главная + закрытая галерея с переключением версии

**Дата:** 2026-06-07
**Статус:** утверждён дизайн, готов к плану реализации

## Проблема

Сейчас корень `/` просто редиректит на `/prototypes/` — публичной «настоящей» главной нет, а галерея прототипов открыта всем. Нужно:

1. На `/` отдавать выбранную боевую версию сайта (как обычный лендинг).
2. Из `/prototypes/` можно выбирать, какая версия — текущая (боевая), без передеплоя.
3. `/prototypes/` закрыть авторизацией (логин через PocketBase).
4. В галерее обозначать, какая версия сейчас на сайте.

Выбран подход **A** (динамический, через PocketBase). Стек прежний: Caddy + PocketBase, без новых сервисов.

## Архитектура

```
                 events-luzern.ch
                        │
                      Caddy
   ┌──────────┬───────────────┬─────────────┬──────────────┐
   /          /assets/*       /login        /prototypes/*   /api/*, /_/
   │          │               │             │               │
 (proxy→PB)  (static:        (static:      forward_auth→PB  (proxy→PB)
  резолвер    prototypes/     login.html)   ↓ ок → static
  current     assets,         публично      file_server
  version)    публично)                     (галерея + все
                                            файлы прототипов)
```

- **Публично:** `/`, `/assets/*`, `/login`, создание заявок (`POST /api/collections/requests/records`, как сейчас), вход (`/api/.../auth-with-password`).
- **За логином:** всё под `/prototypes/*` (включая сырые `.html` прототипов) и переключение боевой версии.

## Компоненты

### 1. PocketBase: коллекция `site_config`

- Одна запись. Поле `current_version` (text), напр. `aurora-v16a.html`.
- Создаётся миграцией; сидируется значением `aurora-v16a.html`.
- Правила доступа: **list/view/update — только аутентифицированный суперюзер**; create/delete закрыты (запись одна, создаётся миграцией). Чтения через публичный API не требуется — резолвер читает запись серверным хуком.

### 2. PocketBase: хуки (`backend/pb_hooks`)

**a) Резолвер главной — `GET /`**
- Caddy проксирует `/` в PocketBase; хук регистрирует роут на `/`.
- Логика: прочитать `site_config.current_version` → собрать путь к файлу внутри смонтированной папки прототипов → если файл существует и имя оканчивается на `.html` и не выходит за пределы папки (защита от path traversal) → вернуть содержимое с `Content-Type: text/html; charset=utf-8`.
- Фолбэк: если запись/файл отсутствует — вернуть простую страницу-заглушку (HTTP 200 или 503 с понятным текстом), не 500.
- Реализационная деталь к подтверждению при имплементации: способ чтения файла из JSVM PocketBase (`$os`/`readFile`-хелпер) и регистрация GET-роута (`routerAdd`/`onServe`). Уточнить под установленную версию PB 0.35.0.

**b) Gate для `forward_auth` — `GET /pb-gate`**
- Читает токен из cookie `pb_auth`.
- Проверяет токен (валидный суперюзерский auth-токен) — напр. через `findAuthRecordByToken`. Валиден → `200`. Иначе → `302` на `/login`.
- `forward_auth` Caddy транслирует ответ клиенту (редирект на логин для незалогиненных).

### 3. PocketBase: монтирование прототипов

- В `docker-compose.yml` добавить read-only монтирование папки прототипов в контейнер PocketBase, чтобы резолвер мог читать файлы версий. Путь монтирования зафиксировать и использовать в хуке.

### 4. Авторизация

- Используется существующий **суперюзер PocketBase** (тот же, что для `/_/`). Отдельная коллекция редакторов не заводится (YAGNI; 1–2 человека).
- Логин на `/login`: форма email+пароль → `POST /api/collections/_superusers/auth-with-password` → при успехе сохранить токен в cookie `pb_auth` (path=/, Secure, SameSite=Lax) и в localStorage → редирект на `/prototypes/`.
- Точный путь auth-эндпоинта суперюзера подтвердить под PB 0.35.0.

### 5. Caddy (`Caddyfile`)

Порядок и блоки (внутри `{$SITE_DOMAIN}`):
- `handle /api/*` → `reverse_proxy pocketbase:8090` (как сейчас).
- `handle /_` и `handle /_/*` → PocketBase (как сейчас).
- `handle /assets/*` → `root * /srv/site/prototypes`, `file_server`, `Cache-Control: public, max-age=31536000, immutable`.
- `handle /login*` → `root * /srv/site`, `file_server` (публично).
- `handle /prototypes/*` → `forward_auth pocketbase:8090 { uri /pb-gate }` (с пробросом Cookie), затем `root * /srv/site` + `file_server`.
- `handle /` → `reverse_proxy pocketbase:8090` (резолвер боевой версии).
- Завершающий `handle { ... }` — статик/404 по необходимости.

Замечания:
- В `/assets/*` при `root /srv/site/prototypes` запрос `/assets/x` отдаёт `/srv/site/prototypes/assets/x` — совпадает с относительными ссылками лендинга (`assets/...`).
- `forward_auth` должен пробрасывать заголовок `Cookie` к `/pb-gate`.

### 6. Галерея `/prototypes/index.html` (доработка существующей страницы)

- При загрузке: если нет/невалиден токен (cookie/localStorage) → редирект на `/login`. (Дополнительно к серверному gate — для UX.)
- Существующий визуал галереи сохраняется. Добавляется:
  - бейдж **«★ LIVE — сейчас на сайте»** у карточки, чья ссылка == `current_version`;
  - кнопка **«Сделать текущей»** на каждой карточке → `PATCH` записи `site_config` (`current_version = <имя файла из ссылки>`) с токеном → обновить бейджи + тост/подтверждение.
- Имя файла версии берётся из `href` карточки (напр. `aurora-v16a.html`).

### 7. Страница входа `login.html` (в корне сайта, публично)

- Минимальная форма email+пароль, обработка ошибок входа.
- При успехе — cookie `pb_auth` + localStorage + редирект на `/prototypes/`.

## Безопасность

- Резолвер отдаёт только `.html` из папки прототипов; защита от path traversal (никаких `..`, абсолютных путей).
- `current_version` меняется только аутентифицированным суперюзером (правило update коллекции + проверка токена на API).
- WIP-версии не доступны публично (gate на `/prototypes/*`).
- Cookie токена: `Secure`, `SameSite=Lax`, `Path=/`.
- Публичный create заявок остаётся как сейчас (без изменения правил `requests`).

## Обработка ошибок

- Резолвер: отсутствует запись/файл → заглушка, не 500.
- Gate: нет/протух токен → 302 на `/login`.
- Галерея: ошибка `PATCH` (протух токен) → сообщение + редирект на `/login`.

## Проверка (смоук на локальном `docker compose`, без юнит-фреймворка)

1. `docker compose up` поднимает стек, миграции создают `site_config` со значением `aurora-v16a.html`.
2. `GET /` возвращает HTML текущей версии; ассеты грузятся с `/assets/...`.
3. `GET /prototypes/` без cookie → 302 на `/login`; с валидным токеном → 200; прямой `GET /prototypes/aurora-v15a.html` без токена → 302/401.
4. Логин на `/login` валидными кредами суперюзера → редирект на `/prototypes/`.
5. «Сделать текущей» для другой версии → `GET /` отдаёт уже её (переключение без передеплоя).
6. Заявка с формы лендинга по-прежнему создаётся (`POST /api/collections/requests/records`).

## Вне области (YAGNI)

- Отдельная коллекция «редакторов» (используем суперюзера).
- Версионная метка на самом боевом лендинге (только бейдж в галерее).
- Статическая регенерация главной в отдельный том (это был вариант B).
- Изменение CI-проверки на «текущий прототип» (остаётся как есть; не мешает).

## Влияние на деплой

- Изменения едут обычным `git push` в `main` → авто-деплой (GitHub Actions) → `docker compose up -d --build`. Новые миграции применяются при старте контейнера PocketBase. `.env` и `data/` на сервере не трогаются.
